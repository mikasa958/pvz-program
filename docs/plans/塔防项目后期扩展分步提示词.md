# Python 塔防项目后期扩展分步提示词

> 项目方向：基于现有 Python + Pygame 塔防原型，进一步扩展为“类 PVZ + 局内强化 + 随机变量 + AI 决策接口”的动态策略塔防环境。  
> 使用方式：每次只复制一个提示词给 Cursor / Codex / 代码助手执行，完成后运行测试，确认无误再进入下一步。

---

## 一、总体开发原则

### 1. 不推倒重写

当前项目已经具备基础塔防闭环，包括：

- 网格地图
- 防御塔放置
- 敌人移动
- 自动攻击
- 资源增长
- 基地血量
- 胜负判定
- AI 模式切换
- 训练适配器
- 日志系统

因此后续扩展必须基于现有代码增量开发，不能重新写一个新项目。

### 2. 优先保护核心接口

以下接口尽量保持兼容：

```python
TowerDefenseEnv.reset()
TowerDefenseEnv.step()
TowerDefenseEnv.valid_actions()
TowerDefenseEnv.get_state()
TowerDefenseEnv.get_render_state()
FastCompatibilityEnv
RuleBasedAgent
```

### 3. 推荐执行检查命令

每完成一个阶段后，至少运行：

```bash
python test_env_compatibility.py
python main.py
```

如果项目中有训练脚本，再额外运行：

```bash
python train_tower_qlearning.py
```

# 六、老师可能追问与回答

## 问题 1：为什么不直接完整复刻植物大战僵尸？

答：
完整复刻 PVZ 会涉及大量动画、素材、关卡编辑、植物技能和僵尸行为，工程量会明显超出当前毕业设计重点。本项目的核心不是复刻商业游戏，而是构建一个可训练、可观察、可扩展的塔防 AI 实验环境。因此我们提取 PVZ 的关键策略机制，例如植物类型、阳光资源、波次推进和敌人差异化，再结合局内强化和随机变量，使环境更适合 AI 决策研究。

## 问题 2：局内强化对 AI 有什么意义？

答：
局内强化会改变当前局面的数值结构，例如攻击力提升、费用降低、阳光产出增加等。这样 AI 面对的不是固定环境，而是会随着强化选择发生变化的动态环境。AI 需要根据当前强化效果调整放置策略，例如选择经济强化后优先发展向日葵，选择攻击强化后优先补充输出植物。这能体现智能体的动态决策能力。

## 问题 3：为什么还使用 Q-Learning，而不是直接用 DQN 或 PPO？

答：
Q-Learning 更适合当前阶段的离散动作空间和教学展示需求，实现简单、可解释性强，也便于观察状态、动作和奖励之间的关系。当前扩展后的环境可以作为 Q-Learning 的实验基础，同时也为后续接入 DQN 或 PPO 提供标准接口。因此 Q-Learning 在本项目中既是可运行的基线算法，也是后续深度强化学习方法的对照组。
